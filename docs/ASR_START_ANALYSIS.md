# Почему пропадает начало разговора после корректной обрезки ожидания

Документ описывает **реальные механизмы** в цепочке «файл → Whisper → текст» и что уже сделано в коде.

## 1. Silero VAD внутри faster-whisper (главный кандидат на 5–10 с)

**Где:** после загрузки WAV модель строит mel, затем `get_speech_timestamps` отрезает участки без «речи».

**Почему бьёт по началу:**

- Порог `threshold`: пока вероятность речи **ниже** порога, сегмент **не открывается**. Тихое «алло», шёпот, линия с шумом → первые секунды **не попадают** в первый speech-chunk.
- `min_speech_duration_ms`: слишком короткие куски **выбрасываются** целиком.
- Первая речь после музыки ожидания часто **слабее** среднего уровня записи — VAD «просыпается» только когда оператор говорит громче.

**Что делаем в коде:** ниже `threshold` / `neg_threshold`, меньше `min_speech_duration_ms`, больше `speech_pad_ms` (паддинг **назад** от первого срабатывания). Аварийно: `CALLQA_ASR_NO_VAD=1` — без VAD (дольше по CPU, зато ничего не вырезается до Whisper).

## 2. Первое окно декодера Whisper (~30 с) и `no_speech_threshold`

**Где:** `generate_segments` в faster-whisper: первый проход — до **30 с** аудио (`chunk_length=30`).

**Почему бьёт по началу:**

- Если модель даёт высокий `no_speech_prob` и **не** срабатывает «спасение» через `log_prob_threshold`, весь кусок **пропускается**: `seek += segment_size` — отбрасывается **до 30 с** (на практике часто заметны именно первые секунды тихого фрагмента внутри окна).

**Что делаем:** подняты `no_speech_threshold` и смягчён `log_prob_threshold` (и для `medium_ru`, не только `ideal_ru`). Для **`ideal_ru`** и **`ultima_ru`** — одна и та же **цепочка температур** декодера (0.0→1.0), если сегмент не проходит пороги compression/logprob.

## 3. Pre-roll перед точкой ожидания (новое)

**Идея:** метка ожидания **точная**, но разрез ровно в `T` даёт декодеру **первый сэмпл = первый слог**. Для VAD/окна это жёсткая граница.

**Решение:** грузим с `offset = T - pre_roll` (например 0.25 с), в буфер попадает короткий **хвост ожидания** перед разговором. Таймкоды в отчёте сдвигаются на **`load_offset`**, а не на `T`, чтобы совпадать с исходным файлом.

**Настройка:** `CALLQA_ASR_PRE_ROLL_SECONDS` (0 отключает).

## 4. Косинусный fade на начале нормализованного WAV

**Проблема:** умножение первых миллисекунд на 0→1 **ослабляет** уже тихий первый слог.

**Решение:** при обрезке ожидания (`skip > 0`) **fade-in отключён**, fade-out на конце файла остаётся.

## 5. Фильтр «галлюцинаций» по `initial_prompt`

**Проблема:** приветствие совпадает со словами из промпта → сегмент мог отбрасываться по overlap.

**Решение:** для фрагментов с `seg_start < 32 с` (после подготовки WAV) фильтр по пересечению с промптом **не применяется**; расширен `_stop_words`.

## 6. Что обычно **не** является причиной «ровно 5–10 с»

- Неточная длительность ожидания в имени файла — при точной метке проблема **после** `T`.
- `librosa.load(offset=…)` — погрешность seek по MP3 обычно **миллисекунды**, не секунды.
- `_split_segment_at_silences` — режет **уже выданный** текст по паузам между словами, не «съедает» начало целиком.

## 7. Чек-лист, если начало всё ещё теряется

1. В логах найти: `ASR pre-roll`, `VAD отключён`, `Отброшен сегмент-галлюцинация`.
2. Включить `CALLQA_ASR_NO_VAD=1` на одном файле — если текст появился, виноват **VAD**.
3. Уменьшить `CALLQA_ASR_PRE_ROLL_SECONDS` или поставить `0`, если в текст лезет мусор из хвоста ожидания.
4. Сохранять во временный **WAV** после подготовки и слушать первые секунды — слышно ли там речь.
